# Home Assistant Add-on: Telemt

MTProto-прокси для Telegram в режиме WEB. TLS терминирует Caddy (или другой
фронт), Telemt получает уже расшифрованный HTTP на порту 18080.

## Что делает аддон

1. Слушает `0.0.0.0:18080` (plain HTTP, только для TLS-терминатора).
2. Принимает carrier-запросы Telegram-клиента и относит их в Telegram.
3. Всё, что не похоже на carrier (обычный `GET /`, боты, сканеры), отдаёт
   маскировочный статический сайт из `/data/public`.
4. Показывает ссылку `tg://webproxy?...` на своей панели (Ingress).

## Что нужно до установки

- **Отдельный поддомен** (`tg.example.com`) с A-записью на ваш публичный IP.
- Аддон [Caddy](https://github.com/ad/ha-caddy) с этим доменом.
- Статический публичный IP: он входит в `public_addr` и участвует в маршруте
  до Telegram. При динамическом IP аддон надо перезапускать после смены.

Можно и без отдельного домена — см. «Вариант на основном домене».

## Опции

### `host` (обязательно)
Публичное имя хоста, например `tg.example.com`. Должно совпадать с доменом
в Caddy.

### `public_ip` (необязательно)
Публичный IPv4 TLS-эндпоинта. Пусто — аддон определит его сам через
`api.ipify.org` при старте.

### `secret` (необязательно)
32 hex-символа. Пусто — генерируется один раз и хранится в `/data/secret`,
переживает перезапуски и обновления.

### `carrier` (по умолчанию `https-lanes`)
`https-lanes` — независимые потоки, быстрее. `https` — старое
сериализованное поведение.

### `log_level` (по умолчанию `normal`)
`debug` | `verbose` | `normal` | `silent`.

### `trusted_proxy_cidrs` (по умолчанию `172.30.32.0/23`)
Откуда приходят запросы от TLS-терминатора. `172.30.32.0/23` — сеть аддонов
Home Assistant, её хватает для аддона Caddy. `0.0.0.0/0` Telemt отвергает.

### `socks5_upstream` (необязательно)
`host:port` локального SOCKS5, через который Telemt будет ходить в Telegram.
Пусто — прямые подключения.

### `decoy_upstream` (необязательно)
`host:port` внутреннего сайта, который Telemt отдаёт вместо маскировочной
статики. Адрес должен быть приватным IP-литералом (`10.x`, `192.168.x`,
`127.0.0.1`). Например `10.0.1.19:8123` — сам Home Assistant. Если задано,
`decoy_html` игнорируется.

Важно: Telemt снимает hop-by-hop заголовки, поэтому **WebSocket через decoy
не проходит**. HA целиком за decoy работать не будет — только корень `/`.

### `decoy_html` (необязательно)
HTML маскировочной страницы. Пусто — простая заглушка «It works.».

## Настройка Caddy

В аддоне Caddy:

```yaml
proxies:
  - domain: tg.example.com
    upstream: 10.0.1.19:18080
    tls: true
```

`10.0.1.19` — IP хоста с Home Assistant. Домен идёт в Telemt целиком.
`security_headers` и `rate_limit` для этого домена лучше не включать:
лишние заголовки и лимиты выделяют прокси на фоне обычного сайта и мешают
long-poll.

## Вариант на основном домене (path_routes)

Отдельный поддомен не обязателен. Telemt слушает четыре фиксированных пути:
`/`, `/api/v1/session`, `/api/v1/up`, `/api/v1/down`. Их можно отдать ему
через `path_routes` в Caddy, а всё остальное оставить Home Assistant:

```yaml
proxies:
  - domain: home.example.com
    upstream: 10.0.1.19:8123
    tls: true
    security_headers: true
path_routes: |
  home.example.com / 10.0.1.19:18080
  home.example.com /api/v1/session 10.0.1.19:18080
  home.example.com /api/v1/up 10.0.1.19:18080
  home.example.com /api/v1/down 10.0.1.19:18080
```

В опциях аддона: `host: home.example.com` и
`decoy_upstream: 10.0.1.19:8123`.

Как это работает: `/` в Caddy матчится точно (без `*`), поэтому в Telemt
уходит только корень. Обычный `GET /` он проксирует в decoy, то есть обратно
в HA — фронтенд открывается как обычно. Все остальные пути, включая
`/api/websocket` и статику, идут в HA напрямую, мимо Telemt, так что
WebSocket не ломается.

Чем этот вариант хуже отдельного домена:

- `rate_limit` на домене режет long-poll. Для этого домена его лучше убрать
  или поднять до нескольких тысяч событий в минуту.
- Маскировка неполная: запрос на `/api/v1/up` без валидных кредов отвечает
  не так, как обычный 404 от HA. Активный сканер это различит.
- Лишний хоп на корне: `GET /` идёт HA → Caddy → Telemt → HA.

Если домен и так светится наружу как Home Assistant, разница невелика.
Если нужна честная маскировка — берите отдельный поддомен и статический
decoy.

## Подключение в Telegram

Открыть панель аддона и нажать на ссылку `tg://webproxy?server=...&secret=dd...`.
Она же пишется в лог при старте. Нужен клиент с поддержкой WEB-прокси
(Telegram Desktop).

## Проверка

- В логе аддона: `Listening on TCP endpoint addr=0.0.0.0:18080 transport=Web`.
- `https://tg.example.com/` в браузере отдаёт маскировочную страницу.
- Если Telegram не подключается — сначала проверьте, что домен в Caddy
  проксируется целиком, без `path_routes`.

## Хранение

```text
/data/secret         секрет WEB-прокси
/data/public/        маскировочный сайт
/etc/telemt/telemt.toml  сгенерированный конфиг (пересоздаётся при старте)
```
